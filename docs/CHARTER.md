1. **完全独立**：新项目与老项目（codex-project）在目录、Git、安装位置、bundle id、

   绝不出现在新项目。

## 1. 定位（继承 POSITIONING.md）

双层定位：
- **里子（功能）**：对抗数字疲劳（Digital Fatigue）——长期面对屏幕后逐渐失去状态。
- **魂（品牌）**：守护你看清世界的方式——眼睛是你和世界之间的通道，恢复不只是
  为了继续工作，是为了屏幕之外还能好好看这个世界。

Slogan：
- 首页体感钩：屏幕看久了，世界会有点糊。／ Mira 陪你，一点点找回清晰。
- 品牌句（仪式时刻）：EyeFlow —— 守护你看清世界的方式。

## 2. v1 功能边界（残酷地小）

v1 只做四件事：

1. **Mira 陪伴**：会呼吸、有气色的胶囊，常驻菜单栏。
2. **提醒**：用眼久了，胶囊气色变淡、提醒你歇一下（该来就来、歇完就安静）。
3. **休息引导**：两种——短歇（眨眼 / 20秒）、完整（小睡 / 自定义时长）。
4. **诚实的记录**：只做"今天"——今天用眼多久、歇了几次，如实呈现，不评判。

**v1 明确不做**：周/月趋势、复杂数据洞察、多种分享卡、一堆可调旋钮、
任何"分析你工作状态"的功能。（记录只做今天；证明有留存后再加周/月。）

**形态**：菜单栏常驻，点开展开面板（大胶囊 + 少量即时数据），无复杂主窗口。

## 3. 核心视觉语言：绿胶囊（精力电池）+ 里面的小 Mira（角色）

新 EyeFlow 独有、别人抄不走的核心识别。关键是"容器 + 角色"两层，不是一个东西：

- **大绿胶囊 = 精力电池 / 核心语言的载体**：一个墨绿的横向胶囊，承载状态、进度线、
  今日数据。它的**绿会随精力变气色**（满电鲜活墨绿 → 低电变淡），是"会变的仪表"。
- **里面的小 Mira = 角色本身**：沿用 app icon 原样（深色胶囊 + 白色圆点眼 + 右上角绿点 +
  柔和光泽），嵌在大绿胶囊左侧，是"她的脸"。**小 Mira 恒定，不随精力忽明忽暗**
  （它是角色，不是仪表）。

统一隐喻（逻辑 / 数据 / 情感三合一）：
> 引擎的"用眼压力上升" = 大绿胶囊的"气色变淡" = 精力电量下降，是同一件事。
> 小 Mira 始终是那张熟悉的脸，住在会变气色的精力胶囊里。

这样两个设计资产都保住：核心语言（绿胶囊=精力电池）成立，app 版 Mira 形象也原封保留。

### 形态分布
- **顶部休息提醒 / 开场大场景**：横向大绿胶囊（气色随精力）+ 左侧嵌小 Mira +
  右侧状态文字 / 进度线。（参考已认可的截图形态。）
- **菜单栏图标**：就用小 Mira（app icon 那个），单色原生、恒定，只表示"在运行"。
- **展开面板**：大绿胶囊为主体（气色 = 当前精力），小 Mira 在其中。

### 状态与形态（小 Mira 的眼睛）
| 状态 | 小 Mira 表现 |
|---|---|
| 安静（日常） | 平和呼吸，偶尔眨眼 |
| 短歇 · 眨眼 | 闭眼即睁（眨一次长眼） |
| 完整 · 小睡 | 深闭眼、缓慢呼吸 |
（精力气色由大绿胶囊承载，不由小 Mira 承载。）

### 配色方向（精确色号见 8.3）
- 大绿胶囊用**绿色的明暗/深浅**表达精力，**不用红黄警示**。
- 满电：鲜活墨绿（气色好）；下降：变暗变淡失光泽（蔫了）；极低：最淡的疲惫绿。
- 低电量传递**共情**（她累了），而非**施压**（警报）。
- 绿色变化靠**降饱和 + 微调明度 + 微透明**，避免发脏——"蔫"要蔫得优雅。

## 4. 菜单栏与展开面板

### 菜单栏图标
- 固定的 Mira 脸（沿用现有形象：圆脸 + 双眼 + 天线），**单色、原生、不变**。
- 只表示"在运行"。**不做气色/精力变化**（菜单栏模板图标受系统单色约束，且太小看不清）。

### 展开面板（点开菜单栏，由开场大胶囊演变而来）
结构 = 数据为主、设置藏一层：
- **主体：大胶囊**（呼吸、气色 = 当前精力）——视觉主角。
- **今日数据**（克制）：今天用眼多久、歇了几次（短歇/完整）、当前精力。
- **动作**：现在歇一下（短歇 / 完整）。
- **设置藏一层**：完整休息时长藏在小齿轮/角落，点开才展开。日常界面只见状态与数据。

## 5. 提醒系统（老项目 L1-L4 重灾区，本次收口）

### 5.1 提醒强度：两级（哪一级触发由系统定，用户不选）
- **一级 · 轻提醒**：精力开始低 → 浮出短歇胶囊，轻引导眨眼 20 秒，可无视、自收起。
- **二级 · 明确提醒**：一直没歇、精力很低 → 提醒更明确（停留久一点 / 建议做完整休息）。
- 这两级是**触发强度**，只由精力电量决定（§5.2），用户不选；提醒的**呈现档位**（顶端岛 / 居中大胶囊）另由用户在设置里选，是正交的一层，见 §6.1、§6.4。

### 5.2 触发依据：只看精力电量（唯一依据）
> 不看前台 app、不看工作强度、不看时间段——只看电量掉到哪条线。

- 电量随连续用眼**单调下降**，休息回充。
- 一级触发：电量跌破线 X → 浮出短歇。
- 二级触发：电量跌破更低的线 Y（Y<X）→ 明确提醒 / 建议小睡。
- 歇完回充，再次跌破才再提醒（**天然安静窗口，无需人为冷却**）。

**为什么只看电量**：老项目该来不来、连环机枪、切 app 乱跳，病根全是"level 每帧从
前台app/负载/idle 这些乱抖信号重算"。只看一个单调、干净、不抖的电量，那些 bug
在结构上没有存在的地方。

### 5.3 电量机制
**放电（下降）**
- 有屏幕活动 = 匀速下降，**固定速度、不个性化**（个性化是 bug 温床，v1 不碰）。
- 短暂离开（几十秒）= 暂停下降，但不回充（你只是在想事情）。
- 真的离开（> 5 分钟）= 当作一次休息、开始回充。

**充电（回升）**
- 短歇（20秒眨眼）→ 回充一小格。
- 完整休息（小睡）→ 回充满。
- 真的离开屏幕（> 5 分钟）→ 自然回充。

### 5.4 引擎建模裁决（2026-07-13 定，用于精力引擎实现）
以下四条收口 5.3 的建模空白，写引擎以此为准（数值仍为 §9.7 可调参数，本节只定结构）：
1. **电量是连续量**：归一化 0–100（或 0–1）的单一连续标量，"一小格 / 一大格"仅为 UI 表达，引擎内部不分格。
2. **离开屏幕的中间地带（几十秒 ~ 5 分钟）= 暂停、不回充**：跨过 5 分钟线之后才开始回充；在此之前电量既不降也不升，原地保持。
3. **完整休息回充至满**：小睡结束电量拉满（= 100），不是"加一大格"。
4. **下限地板为 0**：电量触底后停在 0、不为负，持续表达"极低"状态；二级提醒被无视也不会降到 0 以下。

## 6. 提醒形态与休息体系

### 6.1 提醒形态（精力电池化胶囊，呈现分档位）
- 平时：无胶囊，只有菜单栏 Mira 脸。
- 该歇了 → 浮出横向绿胶囊（Mira 脸 + 一句状态话 + 进度线）。
- **一步**：胶囊浮出 = 直接是 20 秒短歇引导，不分"先提醒再点才开始"。
  你抬眼看远处就是在歇，不看也没关系。
- **自己收起**（tucks away）：20 秒走完自动收回，全程不锁屏、可无视。

**呈现档位（用户在设置里选，见 §6.4）** —— 同一条提醒，两种呈现强度：
- **轻量（默认）**：从**屏幕顶部**浮出的小胶囊（顶端岛），可无视、点穿、自收起。
- **加强**：**居中大胶囊 + 轻微暖背景**（点穿除按钮），更显眼但仍不接管屏幕。
- 档位只改**呈现**，不改触发逻辑：一级/二级仍只由精力电量决定（§5.1/§5.2）。

### 6.2 智能缓冲（键鼠密集时延迟）
- 到点后先看当下键鼠活动。
- 密集操作（在专注）→ 不立刻浮出，缓冲等一个自然间隙才浮出。
- 不密集 → 直接浮出。
- **缓冲有上限**：最多等 5 分钟（可调参数）；5 分钟内出现间隙就顺势浮出，
  始终没间隙则到 5 分钟温和浮出一次——守护眼睛是天职，不能为了不打断而放弃提醒。

### 6.3 休息体系：两层（深度 = 形态深浅）
| | 短歇 · 眨眼 | 完整 · 小睡 |
|---|---|---|
| 时长 | 20 秒（默认，固定不开放） | 自定义（如 1/3/5 分钟） |
| 触发 | 系统自动（浮出提醒） | 用户主动点 / 精力很低时系统建议 |
| 形态 | 提醒胶囊本身，不接管屏幕、可无视 | **边缘柔和雾化 + 柔性阻挡**：屏幕四周渐隐成柔雾、中心留白，笼罩全屏但**不死锁**——轻轻劝退交互，保住"真正离开"的承诺感，不再是旧的全屏纯色接管 |
| 胶囊表达 | 眨一次长眼 | 深闭眼、缓慢呼吸 |

**贯穿的视觉 DNA**：加强档的「暖背景」与小睡的「边缘雾化」是**同一种语言——把世界柔柔推远**，按强度递增（暖 wash 最淡 → 边缘雾化更浓、更包裹）。旧的「全屏纯色接管」退役。

### 6.4 自定义设置（v1 极简）
- **完整休息时长**（如 1/3/5 分钟）。
- **提醒档位**：轻量（顶端岛）/ 加强（居中大胶囊 + 轻微暖背景），默认轻量（见 §6.1）。
- **语言**：中文 / English，首次运行跟随系统语言，之后手选持久化（§4 i18n）。
- **开机自启**：默认开、可关。系统集成项，非"体验旋钮"——菜单栏工具须登录后归位才
  常驻有效；给一个 opt-out 让用户能收回控制权。
- 短歇 20 秒固定，不开放。
- 其余一律不放（不给用户一堆旋钮 = 老项目的坑）。语言与开机自启是 i18n / 系统集成，
  不属于会稀释体验的"参数旋钮"，故与上述两项并列而不违背本原则。

> **已实现回写（2026-07-20 · 待用户确认）**：语言切换与开机自启开关已落地到菜单栏
> 面板设置区，均持久化于隔离 settings.json。开机自启默认开、仅显式关才 opt-out；
> 仅打包签名版注册登录项，dev 不注册。

## 7. 开场流程（首次打开的一次性相遇仪式）

原则：**先体验，后解释；把设置藏进故事；一次相遇仪式。**

1. **登场**：首次打开 = 独立居中欢迎场景（非菜单栏面板），大胶囊呼吸着在屏幕中央登场。
2. **自我介绍**：纯文字浮现（无语音），按 MIRA_LANGUAGE 语气——我是谁 + 不打扰 +
   提醒歇眼 + "先一起试一次"。
3. **第一个 loop**：自动进入短歇——大胶囊闭眼 → 引导看远处 → 20 秒安静（线慢慢走）
   → 睁眼、气色明亮 → 一句让用户当场感受到效果（兑现"守护你看清世界"）。
4. **引导自定义 + 收场**：用刚体验过的短歇对比引出小睡 → 演示深闭眼缓慢呼吸 →
   讲小睡 → 顺势让用户选一次完整休息时长 → "我就在上面陪着你" → 大胶囊演变为常驻
   面板，缩进菜单栏，开场结束。此后不再出现。

（开场所有文案：待视觉原型阶段对着画面最终定调，守笃定不讨好。）

## 8. UI/UX 设计规格

### 8.1 设计标准
- **执行基准：Apple Human Interface Guidelines (macOS)** + Mira"笃定的安静"气质。
- 核心原则：留白优先、克制、精确、少即是多。目标是"用户第一眼就喜欢上这个角色和设计语言"。
- macOS 原生：遵循 HIG 让 app 与系统浑然一体、不违和。

### 8.2 已定方向（精确数值待原型定稿）
- 字体：Apple 系统字体 SF（SF Pro）。
- 间距：基于 8pt 网格（苹果标准）。
- 色彩：绿色明暗表精力，变化路径 = 降明度 + 降饱和 + 微透明（避免发脏）。
- 深色 / 浅色模式各一套色板。
- 动效克制：全产品只有两类持续动 —— Mira 呼吸、状态过渡的轻淡入。

### 8.3 精力配色规格（已锁定 · 2026-07-13 · 以原版顶部胶囊规范为准）

**满电基色（Mira 神采奕奕）：`#1A6B52` / HSL(157, 61%, 26%)**
（继承自老项目顶部胶囊验证过的墨绿 `rgba(26,107,82,0.97)`，深沉、洋气；深墨绿底上
配白眼与薄荷进度线 `#6FE7C3` 对比最佳。之前目测的 `#4BA968` 作废。）

**精力→气色的变化路径**（降饱和为主 + 微升明度 + 微透明，避免发脏，"蔫"得优雅）：
| 精力 | 状态 | 色号 | HSL | 透明度 |
|---|---|---|---|---|
| 100%（满） | 神采奕奕 | `#1A6B52` | H157 S61 L26 | 0.97 |
| ~66% | 常态 | `#2E6B58` | H157 S40 L30 | 0.95 |
| ~40% | 有点淡了 | `#4A6B60` | H157 S19 L36 | 0.92 |
| ~15%（极低） | 蔫了·该充电 | `#5E6B67` | H157 S8 L40 | 0.88 |

规则：色相锁 157（守住"还是墨绿"），靠**饱和度大幅下降 + 明度略升 + 透明度略降**表达
"气散掉、蔫下去"。低电量传递共情（她累了），不转红/黄。中间值线性插值。

### 8.4 顶部胶囊规范（已锁定 · 继承老项目顶部提醒胶囊）

**大胶囊本体**
- 背景：精力满电 `#1A6B52`（随精力按 8.3 变气色）。原始 `rgba(26,107,82,0.97)`。
- 布局：`inline-flex`，尺寸自适应内容，`max-width: 92vw`。
- 圆角：`18px`。
- 内边距：`12px 22px 12px 14px`（左窄给头像留位）。
- 阴影（三层复合，质感关键）：
  `0 12px 34px rgba(0,0,0,0.26)` + `0 6px 16px rgba(0,0,0,0.4)` +
  `inset 0 0 0 1px rgba(255,255,255,0.12)`（内描边高光）。
- 头像与文字区间距：`gap: 13px`。

**左侧小 Mira 头像**：`32×32px`，圆角 `10px`。（形象与渐变光泽见 §8.5，SVG 待补。）

**文字 + 进度线竖排区**：`flex-direction: column`，`gap: 6px`，`min-width: 168px`。

**状态文字**：`16px / 600 / line-height 1.2 / letter-spacing 0.01em`，色 `#f6f7f9`。

**进度线**：底槽 `height 3px`、`border-radius 999px`、`rgba(255,255,255,0.16)`；
填充亮薄荷绿 `#6FE7C3`，宽度随倒计时线性收缩 `transition: width 1s linear`。

**右侧倒计时数字 / ✓**：`15px / 600`，色 `#6FE7C3`，等宽数字（`tabular-nums`）。

**浮出 / 收起动画**：
- 从屏幕顶边后方滑下，`transform: translate(-50%, -190%) → translate(-50%, 0)`，
  `opacity: 0 → 1`。
- 缓动 `cubic-bezier(0.22, 1, 0.36, 1)`，时长 `360ms`；透明度 `280ms ease`。
- 护眼：`prefers-reduced-motion` 时只交叉淡入、不滑动。

## 9. 技术铁律（防复发的出生证）

老项目的血泪，写成新项目从第一天起不可违背的纪律：

1. **不写巨石文件**：逻辑从第一天就分模块，禁止单文件膨胀成万行。
2. **一个事实一个函数一本账**：一个指标只由一个函数产出，绝不多本账各记各的。
3. **纯函数 + 测试先行**：核心逻辑（尤其精力引擎）抽成可独立执行的纯函数；
   先写行为测试（RED），再写实现（GREEN）。
4. **UI 与逻辑分离**：引擎不碰 UI，UI 只消费引擎输出。
5. **一个改动一个 commit**：每个单元独立提交，可追溯、可回退。
6. **命令行验证优先**：装机、构建、状态确认，靠命令行确证，不靠肉眼假设。
7. **可调参数化**：所有体验数值（电量速度、提醒线、缓冲上限等）是参数，
   dogfood 后只调数值、不动引擎。
